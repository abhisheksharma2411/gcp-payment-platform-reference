# payment-platform-reference

The companion module for **Article 11 — How to Build a Production-Grade
Payment Platform on Google Cloud: From Payment Intent to Ledger and
Settlement**.

One command, no cloud project, no credentials, no network:

```bash
make verify
```

Two more that are worth running on their own:

```bash
make happy    # the complete happy path, end to end, with an audit timeline
make inject   # the ambiguous timeout, retried into a second provider region
```

## What it is

An integrated payment platform — three channels, a command API, a provider
adapter with regional endpoints, a durable operation lifecycle, lifecycle
events, a double-entry ledger, settlement ingest, reconciliation exceptions and
an audit timeline — and a **seam auditor** that reports twelve coded findings
about the places where two individually correct components meet.

Every component here is specified in depth by another article in the series.
This module does not restate them. What it owns is the wiring and the
decisions the wiring forces:

| the seam | the decision | where |
|---|---|---|
| two effect-identity derivations meeting at a provider callback | one rule, two derivations, one mandatory join | `ADR-001` |
| four stores holding four correct answers | the authority map declares a divergence window, not only an owner | `ADR-002` |
| the platform's amount rules and the provider's | the platform enforces its own, and records disagreement rather than overriding it | `ADR-003` |
| a checker that shares arithmetic with what it checks | the auditor shares nothing, and the cost of sharing is measured | `ADR-004` |

## The twelve seam codes

| code | meaning |
|---|---|
| `S01_AUTHORITY_WRITE_VIOLATION` | a component wrote a field the authority map gives to another |
| `S02_UNRESOLVED_PROVIDER_REFERENCE` | a provider callback applied an effect it could not attribute |
| `S03_POSTING_WITHOUT_EVIDENCE` | a ledger posting with no provider effect behind it |
| `S04_EVIDENCE_WITHOUT_POSTING` | a provider effect that moved money and was never posted |
| `S05_STALE_READ_BEYOND_WINDOW` | a non-authoritative copy read further behind than it is allowed to be |
| `S06_UNBALANCED_JOURNAL` | the postings for one operation do not sum to zero |
| `S07_ILLEGAL_LIFECYCLE_TRANSITION` | an operation moved along an edge the transition list does not contain |
| `S08_CROSS_TENANT_ACCESS` | a read served one tenant another tenant's record |
| `S09_CARDHOLDER_DATA_OUTSIDE_VAULT` | an account-number-shaped value recorded outside the vault |
| `S10_SETTLEMENT_UNEXPLAINED` | a settlement line that was neither matched nor turned into an exception |
| `S11_POSTED_AMOUNT_MISMATCH` | the posted amount does not equal the amount the command asked for |
| `S12_UNRECORDED_PROVIDER_EFFECT` | settlement evidence of a provider effect the platform never recorded |

Each code has a negative control that must produce that code **and no others**.
A thirteenth control breaks five things at once and is **required to be
rejected** as evidence, because a defect that reddens half the auditor cannot
show which check is doing work.

## The auditor's two restrictions

1. **It reads the trace and the two declarations only** — the authority map and
   the transition list. It never touches a live store, so the same checks could
   run over records a production system wrote, and it fails loudly when the
   platform chose not to write something down.
2. **It shares no code with what it audits.** Its sign convention is a second
   implementation. `make report` measures what that is worth: with the ledger's
   `normaliseMinor` replaced by a truncation, `Ledger.isBalanced` stays green
   and the auditor goes red.

## Layout

```
src/        types, clock, ids, trace, authority map, provider, ledger,

```

## Honesty

Zero runtime dependencies. No `Date.now()` and no `new Date()` anywhere in
`src/`. Everything is synthetic; no card number, real or test-suite, appears
anywhere, and the one account-number-shaped string in the tree is deliberately
not Luhn-valid. `docs/MODEL.md` lists every way this departs from the platform
and the providers it describes, including the ones that weaken its own claims.
